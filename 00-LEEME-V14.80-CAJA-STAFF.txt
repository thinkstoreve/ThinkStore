THINKSTORE MAIN V14.80 · CAJA DEL DÍA PARA STAFF
=============================================

Esta versión es ACUMULATIVA: conserva la versión Main V14.79 (pagos mixtos),
V14.78 (BCV), V14.77 (fotos de perfil) y V14.76 (flujo de venta).

INSTALACIÓN (ORDEN OBLIGATORIO)
1. Crea respaldo y verifica que el entorno real usa la base de datos PRINCIPAL.
2. Supabase principal > SQL Editor: ejecutar MIGRACION-V14.80-CAJA-STAFF.sql.
   Requiere migraciones previas de Main, Staff y pagos mixtos V14.79.
3. Subir este PROYECTO COMPLETO al repositorio Git del sitio Main ThinkStore
   y desplegar en Netlify asegurando que se publiquen /netlify/functions/.
   No usar un deploy estático que omita las funciones.
4. Abrir /staff/ con vendedor / administrador / superadministrador.
5. Ir a Caja, abrir turno con saldos iniciales USD y Bs., confirmar una
   venta de prueba y verificar que se muestre UNA sola vez.
6. Registrar un gasto menor, revisar saldos, validar medios electrónicos,
   contar efectivo, guardar borrador y cerrar el turno.
7. Como administrador, probar reapertura con motivo y consultar el registro.

FUNCIONAMIENTO
- Una caja por persona/día, con hora de Caracas.
- Las ventas confirmadas se leen de pedidos. Los pagos mixtos se leen de
  ts_order_payments (abonos reales) y NO se duplican como entradas manuales.
- Ventas sin atribución a un usuario no se asignan arbitrariamente a una caja.
- La tasa BCV histórica de cada cobro en bolívares se respeta; no se aplica
  retroactivamente la tasa del día de cierre.
- Gasto menor / ingreso extra / retiro / devolución / ajuste se registran
  en ts_staff_cash_movements con creador, método, referencia, concepto y hora.
- Los saldos esperados reflejan EFECTIVO físico, no Zelle ni bancos.
- Pagos electrónicos se marcan como verificados antes del cierre.
- Si hay diferencia, se exige una explicación escrita.
- Reabrir solo admin/superadmin: se exige motivo y queda en auditoría.
- Un cierre almacena una instantánea inmutable de su resumen y movimientos.
- Si Supabase no está disponible, no se permite inventar/guardar cierres offline.
- Gastos de caja se registran en su propia tabla: aún NO se suman de manera
  automática a finanzas/Enterprise para evitar doble contabilidad.
